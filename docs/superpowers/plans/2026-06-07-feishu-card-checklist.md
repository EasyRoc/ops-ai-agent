# 飞书卡片联调 Checklist

> 用途：在真实飞书测试群中验证 AI 兜底、审批回调、重试循环卡片是否按预期工作。每完成一项就打勾；失败时记录现象、Incident 编号、Agent 日志时间点。

## 环境准备

- [ ] Agent 已启动，`http://localhost:8000/health` 返回 `{"status":"ok"}`。
- [ ] PostgreSQL、Redis、Prometheus、K8S demo 服务均在线。
- [ ] `.env` 中已配置飞书应用凭证和测试群 `chat_id`。
- [ ] 飞书测试群已添加当前应用 Bot。
- [ ] 飞书开放平台卡片回调已配置为 `https://公网域名/api/v1/approvals/callback`。
- [ ] 本地公网隧道保持运行，飞书能通过 `challenge` 校验。
- [ ] 本轮测试前已记录 Agent 日志起始时间，方便回溯。

## 1. AI 兜底诊断卡片

适用模板：`fallback_diagnosis_card.json`

### 1.1 卡片整体渲染

- [ ] Header 为黄色，标题包含告警级别、服务名和告警名。
- [ ] 卡片宽屏模式生效，内容没有明显截断。
- [ ] Markdown 正常渲染，包含加粗、换行、代码块。
- [ ] 卡片顶部显示 AI 自主分析提示，能明确看出这是未命中 Runbook 后的兜底方案。

### 1.2 内容验证

- [ ] 根因判断内容与 Web Console / Incident 详情一致。
- [ ] AI 推理过程完整显示，没有被 JSON 转义字符污染。
- [ ] 处置方案按步骤展示，每一步包含风险等级、说明和命令。
- [ ] `kubectl` 命令以代码块格式展示，便于人工复制核对。
- [ ] 验证条件展示完整，包含指标、操作符、阈值和说明。
- [ ] 证据列表展示完整，至少能看到关键指标、日志或 Pod 状态。
- [ ] 置信度显示为百分比。
- [ ] 底部展示 Incident 编号、当前状态和耗时。

### 1.3 按钮交互

- [ ] `AI 自动执行` 按钮可点击，点击后 Agent 收到 `/api/v1/approvals/callback` 回调。
- [ ] 点击 `AI 自动执行` 后，数据库中 `approval_status` 变为 `ai_approved`。
- [ ] 点击 `AI 自动执行` 后，飞书原卡片被替换为审批结果卡片，原按钮消失。
- [ ] `我自己来` 按钮可点击，点击后数据库中 `approval_status` 变为 `manual_executing`。
- [ ] 点击 `我自己来` 后，不会触发自动执行工作流。
- [ ] `拒绝` 按钮可点击，点击后数据库中 `approval_status` 变为 `rejected`。
- [ ] 点击 `拒绝` 后，不会触发自动执行工作流。
- [ ] 同一张卡片按钮被点击一次后，后续不应再看到可继续操作的原按钮。

## 2. 重试卡片

适用模板：`retry_card.json`

### 2.1 卡片整体渲染

- [ ] Header 为橙色，标题包含 `第 N/5 轮重试`。
- [ ] 卡片宽屏模式生效，历史摘要没有明显截断。
- [ ] 第 2 轮、第 3 轮等不同轮次标题显示正确。
- [ ] 最后一轮显示为 `第 5/5 轮重试`，不会出现第 6 轮卡片。

### 2.2 内容验证

- [ ] 卡片顶部展示当前重试轮次。
- [ ] `上轮失败原因` 能看到上一轮执行或验证失败的原因。
- [ ] `本轮自省分析` 能看到 LLM 对失败原因的修正判断。
- [ ] `本轮修正方案` 展示新的处置步骤和命令。
- [ ] `验证条件` 与本轮方案中的验证规则一致。
- [ ] `历史摘要` 按轮次顺序展示，包含前几轮的操作和结果。

### 2.3 按钮交互

- [ ] `继续 AI 执行` 按钮可点击，点击后数据库中 `approval_status` 变为 `retry_continue`。
- [ ] 点击 `继续 AI 执行` 后，Agent 触发重试工作流。
- [ ] 点击 `继续 AI 执行` 后，飞书原卡片被替换为审批结果卡片，原按钮消失。
- [ ] `转人工` 按钮可点击，点击后数据库中 `approval_status` 变为 `escalated`。
- [ ] 点击 `转人工` 后，不再继续自动重试。
- [ ] 按钮 value 中的 `round` 字段与卡片标题中的轮次一致。

## 3. 审批结果卡片

适用模板：由 `build_approval_result_card()` 生成。

- [ ] `ai_approved` 状态显示为已批准 AI 自动执行。
- [ ] `manual_executing` 状态显示为已转人工执行。
- [ ] `retry_continue` 状态显示为已批准继续重试。
- [ ] `rejected` 状态显示为已拒绝。
- [ ] `escalated` 状态显示为已转人工或已升级人工处理。
- [ ] 所有审批结果卡片均不包含 action 按钮。
- [ ] 卡片底部提示审批状态已写入 Incident，原操作按钮已失效。

## 4. 整体流程验证

### 4.1 AI 兜底自动执行流程

- [ ] 发送未知告警。
- [ ] 飞书收到 AI 兜底诊断卡片。
- [ ] 点击 `AI 自动执行`。
- [ ] Agent 日志出现审批回调、状态更新、重试工作流启动记录。
- [ ] Web Console 能看到执行记录或重试记录。
- [ ] 审计日志包含 `ai_plan_generated`、`approval_callback_received`、`ai_execution_approved` 等关键事件。

### 4.2 人工处理流程

- [ ] 发送未知告警。
- [ ] 点击 `我自己来`。
- [ ] Incident 状态变为 `manual_executing`。
- [ ] 没有新增自动执行记录。
- [ ] 飞书原按钮消失。

### 4.3 拒绝流程

- [ ] 发送未知告警。
- [ ] 点击 `拒绝`。
- [ ] Incident 状态变为 `rejected`。
- [ ] 没有新增自动执行记录。
- [ ] 飞书原按钮消失。

### 4.4 重试流程

- [ ] AI 自动执行后验证失败。
- [ ] 飞书收到第 2 轮重试卡片。
- [ ] 点击 `继续 AI 执行`。
- [ ] Agent 执行第 2 轮方案。
- [ ] 如果仍未恢复，飞书收到第 3 轮重试卡片。
- [ ] 重复直到恢复或达到 5 轮上限。
- [ ] 达到 5 轮上限后，Incident 状态升级为人工处理，不再生成第 6 轮卡片。

## 5. 排障记录项

出现异常时，建议至少记录以下信息：

- [ ] Incident 编号。
- [ ] 飞书卡片类型和按钮名称。
- [ ] 点击按钮的本地时间。
- [ ] Agent 日志中对应的 `审批回调入口`、`飞书卡片动作`、`审批状态已更新` 记录。
- [ ] `/api/v1/incidents/{incident_id}` 返回的当前状态。
- [ ] `/api/v1/incidents/{incident_id}/audit` 返回的审计事件。
- [ ] 是否成功调用飞书 `update_card`。

## 6. 自动化测试补充

手动联调前，建议先运行：

```bash
.venv/bin/python -m unittest tests.test_templates tests.test_approvals -v
```

通过标准：

- [ ] `fallback_diagnosis_card` 模板测试通过。
- [ ] `retry_card` 模板测试通过。
- [ ] `approve_ai`、`manual_fix`、`continue_retry`、`stop_retry` 回调映射测试通过。
- [ ] 审批结果卡片不再包含 action 按钮的测试通过。
